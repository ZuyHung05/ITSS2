## Environment and isolation

- Actual Spring Boot application, Thymeleaf FE, Spring Security form login, real session cookies/CSRF and PostgreSQL 14.20. Chrome headless through Playwright; no mocked business API or database. Only test fixture/time and explicit UI failure injections are controlled.
- Test-classpath-only server: `BE/src/test/java/com/example/demo/acceptance/AcceptanceServer.java`. It starts and owns its temporary PostgreSQL, binds HTTP to 127.0.0.1:18083, rejects a datasource URL that differs from its own instance, and disables automatic scheduled jobs. No Supabase/shared/production connection is opened by these tests.
- Reset/clock/job controls require a per-process random header key and exist only in test classes under profile acceptance. The runtime key is not included in this report or committed evidence.
- Before every scenario, only the owned temporary DB is reset. UUIDs are generated from fixture aliases, seeded and obtained from the running server. Fixture aliases are recorded in every case JSON. Two projects, eight users and nine tasks (the eight planned tasks plus an isolation task in P2).
- Tests use Friday 15:29, 15:30, 21:59, 22:00 and 22:01, plus Wednesday/next Friday. Actual database timestamp reads and UTC server settings verify the boundary semantics.

## Defects found and fixes

1. **Premature jobs:** the original job service created reminders before 15:30 and final alerts at 21:59 when invoked directly. F03-09/F03-13 reproduce this in the initial run. Fix: production job execution validates the selected Friday and server-side time, including after acquiring the project lock. The explicitly secured demo simulation remains separate. Files: `BE/src/main/java/com/example/demo/service/CheckpointJobs.java`, `BE/src/main/java/com/example/demo/controller/DemoJobsController.java`.
2. **Task detail navigation:** UI-02 found no explicit back-to-My-Tasks link. Fix in `FE/static/assets/app.js`.
3. **Lost acknowledgement on task creation:** UI-14 commits a real POST then drops only its response. Originally retrying created a second task. Fix: one request UUID per form submission, backed by the existing task primary key, server-side payload/authorization checks and conflict-safe insertion. No migration, new table or production data change is needed. Files: `dto/Requests.java`, `controller/ApiController.java`, `service/HanareService.java`, `repository/HanareRepository.java`, `FE/static/assets/app.js`.

The lost-ack defect was reproduced after correcting the test locators: [before-fix log](docs/test-evidence/solution1/lost-ack-regression-before-fix.log), [actual DB evidence showing two rows](docs/test-evidence/solution1/initial-failures/UI-14-lost-ack.json).

Test harness corrections are distinguished from application fixes: F03-04 initially demanded 403 although the plan explicitly permits 403 or 404; the missing dedicated support URL correctly returned 404 without private data. UI-03/UI-14 used exact label-text locators that included textarea/select child text; accessible textbox/combobox role locators are now used, without weakening the assertions. SAFE-01 now calls PostgreSQL host(inet_server_addr()) instead of incorrectly comparing its CIDR text representation with a plain address. These initial failures remain in the logs; they are not reported as application defects.

See the initial failed-case evidence/logs and the executed rerun above for verification.

## Requirement clarifications and existing schema limits

- F01-04 is tested as write denial (403) plus a read-only detail screen. The master permissions matrix explicitly permits project members to view team task progress; denying that read merely to force a 403 on the public task URL would change the product. The edit action is absent and the direct PATCH is forbidden.
- Private support resource GET is denied to peers, while public task detail excludes private requests. Need Help and Solution 2 volunteer help remain distinct; Solution 2 handoff is disabled because the route does not exist.
- DONE and reports are counted separately. No completion timestamp, immutable historical weekly snapshot, persistent checkpoint Reviewed acknowledgement or interim milestone table was fabricated. Past dashboard colors cannot establish historical/on-time performance; task reports remain queryable and read-only after cutoff.
- Notification visibility is refresh/poll based, not push/email. The real deployment must keep the app running at the scheduled times.
